Grid fps note: `grid_bench` advances one scroll step per `on_next_frame`, and each step also builds synthetic result pages on the UI thread. The figure is therefore the frame cost of the whole bench loop (p95 43.51 ms vertical, 42.57 ms horizontal, narrow; 60 fps needs ≤ 16.7 ms), not a pure paint cost, and it does not move when the virtual monitor refresh is raised from 60 to 120 Hz. Treat it as a conservative lower bound.

## Method

- **Start**: `SELA_BENCH_STARTUP=1` makes the first `Workspace` frame print the wall-clock epoch (ns) on stderr; the script subtracts the timestamp it took just before `exec`. This covers process start, GPU/window setup and first paint of the window with the sidebar. Each run uses a fresh config dir with 3 saved connections (SQLite sample file, Postgres, MySQL; none connected) and a warm page cache.
- **Idle memory**: `VmRSS` from `/proc/<pid>/status` of the first run, 5s after the first frame, nothing connected. Connected-session memory is not covered by this script.
- **Grid**: `cargo run -p sela-app --release --example grid_bench` (narrow and `--wide-unique`); protocol in [dev/benchmarks.md](./dev/benchmarks.md#method). Baseline RSS narrow 88.9 MiB → end 113.1 MiB; wide-unique 89.4 MiB → end 139.1 MiB. Time to first frame of the grid itself: 36.3 ms.
