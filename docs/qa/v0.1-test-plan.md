# Sela v0.1.0 test plan

Release QA for the M1 candidate on `main` at `73ae3d8` (PRs #9–#26). This plan does not change product code. Automated coverage and the five highest-risk gaps are in [v0.1-gap-analysis.md](./v0.1-gap-analysis.md).

Commit under test: `73ae3d8ac22c8b93d17aafbb5f249b46f7c9f8bb` (`fix(copy): quote or refuse non-finite floats in INSERT`).

## Scope

In scope for v0.1.0 (M1, daily read-only use):

- Connections to PostgreSQL 16, MySQL 8.4, and SQLite, including TLS modes `prefer`, `require`, `verify-ca`, and `verify-full`, and the negative cases below.
- Tabs (open, close, switch, restore, cancel-on-close).
- Result streaming with the 1 000-row SQL cap, load-more, and cancel.
- Filter and sort: bound values, `LIKE` escaping of `%`, `_`, and the escape character `!`, AND-only combination.
- SQL editor: run at caret, run selection, run all; dialect-aware statement splitting (Postgres `$$` / `$tag$`, comments, quoted strings); stop on the first error.
- Query history: FTS search, rerun confirmation for statements that are not read-only, password-bearing DDL not saved, Clear history.
- Copy as TSV, CSV, JSON, and INSERT: the text `NULL` versus a real NULL, refusing unloaded rows, `NaN` / `Infinity`.
- Light, dark, and system themes.
- Keyboard shortcuts. The secondary modifier is Command on macOS and Control on Linux and Windows (`secondary-` in gpui-pre 0.3.12).
- Postgres display fallback: known text forms, and `<TYPE>` for unsupported or unknown types.
- Quitting the application: shortcut, File > Quit, last-window close, and a confirm dialog while a query is running. The owner reports there is no usable quit path on the candidate; the cases below are the acceptance bar for the fix.

Out of scope (later milestones, do not fail v0.1.0 for their absence): cell editing and safe mode (M2), SSH (M3), autocomplete and SQL grammar highlighting (M3-2), full-table export (M3-3), command palette (M3-4), signed installers and NFR sign-off on a real GPU (M4). Documented M1 limits stay limits: SQLite cancel only drops the stream; `SELECT my_func()` is still classified as safe to re-run; client keys must be unencrypted PEM; MySQL live TLS is not in CI today.

## Risks

| Risk | Why it matters for v0.1.0 |
| --- | --- |
| No usable Quit | `cmd-q` is the Super key on Linux, not Control. There is no File menu and no close control under Wayland client-side decorations. A desktop build users cannot leave is a release blocker. |
| Password DDL hole | `CREATE/ALTER USER … IDENTIFIED WITH mysql_native_password BY '…'` is not treated as password DDL. The password is eligible for `history.sqlite` (mode `0600`, not encrypted). |
| `LIKE` escape vs the tooltip | The filter tooltip and `docs/user/filtering.md` tell the user to type `!` before a literal `%` or `_`. The builder doubles every `!`, so that pattern does not match a literal percent. |
| TLS negatives and MySQL TLS are thin | CI covers four Postgres cases. A bad CA, `require` against a server with TLS off, `prefer` falling back to plaintext, and all MySQL live TLS modes are untested. |
| Run-all / caret / selection live in the GPUI shell | `split_statements` is unit-tested. Which statements actually run, and that a failure or cancel does not start the next one, is not. |
| Workspace tests go green while skipping servers | Forgetting the URL env vars hides driver regressions. |
| `prefer` is the new-connection default | It may fall back to plaintext. The dialog says so; a remote server that speaks both still needs `require` or `verify-full`. |
| SQLite cancel | Dropping the stream does not interrupt the SQLite call. Documented. |
| `SELECT my_func()` | Classified as safe for load-more and for history rerun. Documented. |
| Windows CI is not on pull requests | A Windows-only GPUI or keychain failure can ship. |
| Headless GPU | Cold start and scroll fps are not re-measured here. Roadmap already defers a real-GPU check. |

## Spec ambiguities (not filed as bugs)

- **Thousands separators in row counts.** UX `04-query-history.md` writes examples as `~1,000 rows` and `1,000+ rows`. `history_rows_label_for_rows` and `format_status_line` emit `~1000 rows` and `1000+ rows`, and the unit test locks that. Treat the comma as English prose unless product wants grouping. Do not fail the release on it.
- **Compositor close versus an app-owned Quit.** On Linux and Windows, gpui-pre `QuitMode::Default` calls `App::quit` when the last window is removed. Sela never sets the mode. Wayland windows start as client-side decorations, and Sela does not render `TitleBar`, so there is often no close button to remove the window. If a compositor close does arrive (Alt+F4, or server-side decorations on X11), Linux quits immediately with no running-query confirm. macOS `QuitMode::Default` does **not** quit when the last window closes. The quit cases below are the product contract; the GPUI default is not a substitute, and a fix should not skip the confirm just because the platform already quit.
- **`cmd-` versus `secondary-`.** gpui-pre 0.3.12 maps `cmd` / `super` / `win` to the platform modifier (Command on macOS, Super/Logo on Linux) and maps `secondary` to Command on macOS and Control elsewhere. Older Sela bindings register both `cmd-` and `ctrl-`, so those chords still work on Fedora. Quit is the binding that is `cmd-q` only. That is a defect (filed), not an open question about the parser.

## Test cases

Priority: **P0** blocks the release, **P1** should be fixed or written into the notes, **P2** is polish. Automation: **auto** means a crate test or a CI job that already asserts it; **manual** means a person at a display (Fedora checklist unless a case says otherwise). A case can be both: the library behavior is auto, the window is manual.

### Connections and TLS

#### TC-CONN-01 — SQLite sample library

- **Priority:** P0
- **Automation:** auto (`sela-drivers` `sqlite::sample_catalog_preview_and_paging`, `refuses_to_create_a_missing_file_unless_asked`) + manual open

#### TC-CONN-02 — PostgreSQL 16, mode `prefer`, server without TLS

- **Priority:** P0
- **Automation:** manual (live `prefer` is not in CI; `tls::maps_every_postgres_mode` only checks the sqlx enum)

### Result streaming

#### TC-STRM-01 — 1 000-row cap

- **Priority:** P0
- **Automation:** auto (`sqlite::sqlite_sql_cap_and_load_more`; `DEFAULT_SQL_ROW_CAP` is 1000). Manual for the status line.
- **Preconditions:** A table or `SELECT` that yields at least 1 500 rows. Query tab, not a table preview.
- **Steps:** Run `SELECT id FROM nums ORDER BY id` (or generate 1 500 rows).
- **Expected:** The grid receives 1 000 rows and stops. Status/count kind is “at least” (`1000+`), `truncated` is set. The statement is not wrapped in `SELECT * FROM (…) LIMIT`. Table previews still page at 100 rows (`PAGE_SIZE`) and are not cut at 1 000.

#### TC-STRM-02 — Load more on a read-only statement

- **Priority:** P0
- **Automation:** auto (same SQLite test raises the cap to 1 500 and also pauses a live stream at the cap; `sql::load_more_rerun_allows_only_safe_reads`)
- **Preconditions:** TC-STRM-01 result still on screen, stream finished or paused.
- **Steps:** Load more once.
- **Expected:** Cap becomes 2 000 (or the next 1 000). New rows append. A pure `SELECT` / `VALUES` / `WITH` without DML, `SHOW`, and `EXPLAIN` without `ANALYZE` may re-run if the stream is gone. Row order stays `ORDER BY`.

#### TC-STRM-03 — Load more refuses unsafe SQL

- **Priority:** P0
- **Automation:** auto (`sqlite::sqlite_dml_returning_must_not_rerun_on_load_more`, classifier tests in `sql.rs` and `history::rerun_confirm_follows_load_more_classifier`)
- **Preconditions:** A statement that writes or is `EXPLAIN ANALYZE`, capped.
- **Steps:** Load more.
- **Expected:** No second execution. Status: `Result capped at N rows. Re-run manually to see more.` Note says re-running could repeat side effects. `INSERT`/`UPDATE`/`DELETE`/`SELECT … INTO`/`FOR UPDATE` are refused. Known limit: `SELECT my_func()` is still allowed.

#### TC-STRM-04 — Cancel

- **Priority:** P0
- **Automation:** auto (`postgres_cancel_sleep_within_one_second`, `postgres_cancel_does_not_poison_next_query`, and the MySQL twins). SQLite has no server cancel; manual check that the UI unlocks. Shortcut is manual.
- **Preconditions:** `SELECT pg_sleep(30)` (MySQL `SELECT SLEEP(30)`) on a query tab.
- **Steps:** Stop, and on a second run Secondary+. (⌘. / Ctrl+.). Then run `SELECT 1` on the same tab.
- **Expected:** UI shows Cancelling, then Cancelled, with rows already received kept. Postgres `pg_cancel_backend` / MySQL `KILL QUERY` from a second connection; the cancelled connection is not reused for the next query. Wall time to cancel is within about 1 second. The next statement succeeds. SQLite only drops the stream (documented); the UI must still leave the running state.

#### TC-STRM-05 — Bounded window and decode errors

- **Priority:** P1
- **Automation:** auto (`result_window::eviction_keeps_pages_near_viewport`, `cell_value_returns_full_untruncated_text`; `types::truncate_one_line_newlines_and_utf8_boundaries`, `json_stays_raw_until_parsed`; `decode::raw_access_error_is_other_not_null`)
- **Preconditions:** A wide text or JSON cell longer than 200 characters, and a value that fails decode.
- **Steps:** Scroll so early pages leave the 16-page window. Copy the long cell (see copy cases). Inspect a decode-error cell.
- **Expected:** At most 16 pages of 100 stay resident unless the cap is raised for a fully materialized result. Display is one line, about 200 scalars, newlines as `⏎`. Copy uses the full value. A decode failure is `Value::Other` / `<TYPE>` style, never SQL NULL. JSON is stored as raw text.

### Filter and sort

#### TC-FILT-01 — Values are bound (no SQL injection)

- **Priority:** P0
- **Automation:** auto (`filter::injection_attempt_is_a_bound_literal`, `quotes_and_binds_equality_per_dialect`; live rows in `sqlite::filter_and_sort_bound_params_with_special_chars`, `postgres_filter_and_sort_when_configured`, `mysql_filter_and_sort_when_configured`)
- **Preconditions:** Table `sela_filter` shape from those tests, or any text column. Table Data tab (not a SQL result).
- **Steps:** Filter `name` `=` `drop; --` and Apply. Also `'` and a quote in an identifier column if you have one.
- **Expected:** The value is a bound parameter (`$1`, `?`). It is not concatenated into the SQL. The row whose name is the literal `drop; --` matches. Identifiers are quoted (`"`, backticks on MySQL). The predicate strip shows placeholders, not the value interpolated as SQL. The editor buffer is unchanged.

#### TC-FILT-02 — `LIKE` escaping of `%`, `_`, and `!`

- **Priority:** P0
- **Automation:** auto for legacy **contains / starts / ends** (`filter::like_escaping_and_ilike_on_postgres`, `mysql_like_uses_bang_escape_not_backslash`, and the three engine tests with `FilterOp::Contains`). The menu operator `LIKE` is **not** covered the way the user guide describes it; see the defect below.
- **Preconditions:** Rows `100%`, `a_b`, `wow!`, `Ada`.
- **Steps:**
  1. Operator `LIKE`, value `%`. Apply.
  2. Operator `LIKE`, value `100!%`. Apply.
  3. Operator `LIKE`, value `a!_b`. Apply.
  4. Operator `LIKE`, value `wow!!`. Apply.
  5. Operator `LIKE`, value empty. Apply.
  6. Restored legacy `contains` of `%` (tabs.json), if you can load one.
- **Expected (contract in `docs/user/filtering.md` and the operator tooltip):** `%` and `_` are wildcards. `!` escapes the next character. `!!` is a literal `!`. SQL is `LIKE ? ESCAPE '!'` (Postgres `LIKE`, not `ILIKE`, for the menu operator). Step 1 matches every non-null name. Step 2 matches only `100%`. Step 3 matches only `a_b`. Step 4 matches only `wow!`. Step 5 is rejected (`Enter a pattern`) and does not change the page. Contains still wraps the escaped literal in `%…%` and matches one row for `%`.
- **Actual on `73ae3d8`:** `escape_like_meta` doubles every `!`, and `filter::validate_empty_text_eq_and_reject_null_literal_on_int` expects `a%!b` to bind `a%!!b`. Step 2 then means “wildcard, literal `!`, wildcard”, not the row `100%`. File this; do not “fix” the test plan to match the bug.

#### TC-FILT-03 — AND only

- **Priority:** P0
- **Automation:** auto (`filter::and_combines_multiple_conditions`, `null_ops_have_no_params`, `in_list_binds_each_item_in_order`)
- **Steps:** Two rows: `id = 1` AND `name` `is not null`. Apply. Confirm there is no OR control.
- **Expected:** `WHERE` joins with `AND` only. `IS NULL` / `IS NOT NULL` add no parameter. `IN` binds each item. Invalid any row (empty column, `LIKE` on an int, `NULL` typed into an int `=`) refuses the whole Apply and leaves the previous page.

#### TC-FILT-04 — Sort

- **Priority:** P0
- **Automation:** auto (`filter::sort_and_page_append_order_limit`; live `ORDER BY` in the three engine filter tests). Click behavior is manual.
- **Steps:** On a table Data tab, click a header, click it again, click it again. Shift-click two more columns. Shift-click a fourth. Open a SQL result and click a header.
- **Expected:** Cycle is asc → desc → none when that column is the only key; otherwise a plain click replaces the list with that column ascending. Shift-click adds up to 3 keys, marks like `title ▲1` / `author ▼2`. SQL is `ORDER BY` on quoted identifiers, not a client-side sort of the page. SQL result tabs do not header-sort. Applying filter or sort re-queries from page 0 and cancels the in-flight request.

#### TC-FILT-05 — Filtered count

- **Priority:** P1
- **Automation:** partial (`query::unknown_filtered_status_matches_ux`). The ticking cancel path is manual.
- **Steps:** Apply a filter. Read the status bar. Press Count. Press Stop during Count.
- **Expected:** While filtered, status is `unknown rows · N on this page` and the page label has no stale total. Count runs `COUNT(*)` with the same `WHERE`. Status ticks `Counting… · {elapsed}`. Cancel shows `Count cancelled`, grid unchanged, no error banner. A failed count shows `Count failed · …` and does not set `view.error`.

### SQL editor

#### TC-SQL-01 — Run at caret

- **Priority:** P0
- **Automation:** manual (splitter units exist; the editor path does not)
- **Preconditions:** Query tab, SQL editor focused. Buffer:

  ```sql
  SELECT 1;
  SELECT 2;
  ```

- **Steps:** Place the caret in `SELECT 2`. Secondary+Enter. Then place the caret in the gap or the leading comment above `SELECT 1` and run again.
- **Expected:** Only the statement that owns the caret runs. A caret in the leading comments belongs to the first statement. The other statement does not run. Focus outside the editor does not run SQL (a filter field Applies instead).

#### TC-SQL-02 — Run selection

- **Priority:** P0
- **Automation:** manual
- **Steps:** Select both statements in TC-SQL-01, Secondary+Enter. Then select only the text inside one string literal that contains a semicolon (`'a;b'`).
- **Expected:** A non-empty selection is split and run (both statements, sequentially). A semicolon inside quotes is not a split. An unclosed quote in the selection sets the local error `Unclosed quote` and does not hit the server.

#### TC-SQL-03 — Run all, stop on first error

- **Priority:** P0
- **Automation:** manual (no test drives `finish_sql_statement`)
- **Preconditions:** Editor focused. Buffer, with a table you can afford to touch:

  ```sql
  SELECT 1;
  SELECT * FROM does_not_exist;
  CREATE TABLE sela_should_not_exist (id int);
  ```

- **Steps:** Secondary+Shift+Enter. After the error, check the catalog for `sela_should_not_exist`. Repeat with a 9-statement success script.

### Draft — Quit (severity:blocker)

**Title:** No usable way to quit Sela (shortcut, menu, or last-window close)

**Environment:** `main` `73ae3d8`. Fedora / any Linux (Control is the secondary modifier). Also macOS for last-window close. gpui-pre 0.3.12, gpui-kit 0.10.0. Headless code inspection plus gpui-pre sources in the cargo registry (no display run).

**Steps to reproduce:**

1. Build `sela` from `73ae3d8` and open the window on Fedora (Wayland).
2. Press Ctrl+Q with the SQL editor focused, again with a result cell focused, and again with the connection dialog open.
3. Look for a File menu and a Quit item.
4. Look for a title-bar close button under Wayland client-side decorations.
5. Start `SELECT pg_sleep(60)` and try to leave the app.

**Expected:** Ctrl+Q / Cmd+Q (the secondary modifier) quits. File > Quit quits. Closing the last window quits. If a query is running, a confirm dialog appears; Cancel leaves the app and the query running; Confirm cancels the query and exits with no orphan `sela` process. Idle quit exits immediately.

**Actual:**

- The only binding is `KeyBinding::new("cmd-q", Quit, None)` in `crates/sela-app/src/ui/mod.rs`. There is no `ctrl-q` and no `secondary-q`. In gpui-pre 0.3.12, `cmd` sets the platform modifier. On Linux that is the Super/Logo key (`MOD_NAME_LOGO` in `gpui-pre-linux` `modifiers_from_xkb`), not Control. `secondary` is Control on Linux and Command on macOS. GNOME usually consumes Super, so Ctrl+Q does nothing and Super+Q does not reach the app. `docs/user/keyboard-shortcuts.md` lists Quit as `Cmd+Q` only.
- There is no application menu and no File > Quit anywhere in `sela-app`.
- `Quit` is handled by `cx.on_action(|_: &Quit, cx| cx.quit())`. No confirm, and the running query is not cancelled first.
- Sela never calls `set_quit_mode` and does not render gpui-component `TitleBar`. Wayland windows start as client-side decorations (`WindowDecorations::Client` in `gpui-pre-linux`). Close/min/max buttons are drawn only by that `TitleBar`, which this app does not use, so a Fedora Wayland window often has no close control. GPUI `QuitMode::Default` would quit on non-macOS **if** the window were removed, and would **not** quit on macOS. That default is not a confirm-and-cancel path.

**Evidence:** `crates/sela-app/src/ui/mod.rs` (binding and `cx.quit()`); gpui-pre 0.3.12 `platform/keystroke.rs` (`cmd` vs `secondary`); `gpui-pre-linux` `modifiers_from_xkb`; `app.rs` `QuitMode::Default`; `gpui-component` `title_bar.rs` (Linux close button calls `window.remove_window` only when `TitleBar` is rendered and decorations are client-side).

**Severity:** blocker. A packaged desktop app with no reliable way to exit should not ship as v0.1.0.

### Draft — Password DDL (severity:blocker)

**Title:** MySQL `IDENTIFIED WITH … BY` password DDL is saved to query history

**Environment:** `main` `73ae3d8`. Library probe, no GUI. `history.sqlite` is mode `0600` and not encrypted.

**Steps to reproduce:**

1. Call `sela_core::history_sql_contains_password_clause` (or run the statement from the SQL editor with Record query history on) for:
   - `CREATE USER 'u'@'%' IDENTIFIED WITH mysql_native_password BY 'secret'`
   - `ALTER USER 'u'@'%' IDENTIFIED WITH mysql_native_password BY 'secret'`
   - `CREATE USER 'u'@'%' IDENTIFIED WITH caching_sha2_password BY 'secret'`
   - `CREATE USER u IDENTIFIED WITH auth_plugin BY 'secret'`
2. Search history for `secret`.

**Expected:** All four are skipped. Status note `not saved to history (contains a password)`. `caching_sha2_password` is the MySQL 8 default plugin. A `SELECT` of a column named `password`, and the same DDL inside a comment, are still recorded.

**Actual:** The helper returns false for all four. Adjacent `IDENTIFIED BY` and `CREATE/ALTER USER/ROLE … PASSWORD` are detected (unit test `password_setting_ddl_is_not_recorded`). `IDENTIFIED` and `BY` must be neighboring words, so `IDENTIFIED WITH <plugin> BY` misses. `mysql_native_password` is one word. `caching_sha2_password` splits on the digit into `caching_sha` and `_password`, and `_password` is not the keyword `password`, so the `CREATE USER` + later `PASSWORD` rule also misses.

**Evidence:** Probe against `sela-core` 0.1.0 at `73ae3d8`:

```text
password_clause=true    CREATE ROLE x WITH LOGIN PASSWORD 'secret'
password_clause=true    CREATE USER 'u'@'%' IDENTIFIED BY 'secret'
password_clause=false   CREATE USER 'u'@'%' IDENTIFIED WITH mysql_native_password BY 'secret'
password_clause=false   ALTER USER 'u'@'%' IDENTIFIED WITH mysql_native_password BY 'secret'
password_clause=false   CREATE USER u IDENTIFIED WITH auth_plugin BY 'secret'
password_clause=false   CREATE USER 'u'@'%' IDENTIFIED WITH caching_sha2_password BY 'secret'
password_clause=false   SELECT password_hash FROM users
password_clause=false   CREATE TABLE t (password text)
```

Tokenizer of the caching form: `CREATE, USER, u, IDENTIFIED, WITH, caching_sha, _password, BY, secret`.

**Severity:** blocker. The release notes say this class of statement is not saved. The default MySQL 8 form writes the password into `history.sqlite`.

### Draft — LIKE escape (severity:major)

**Title:** Filter LIKE `!` escape does not match a literal `%` or `_`

**Environment:** `main` `73ae3d8`. `sela-core` filter builder. Tooltip in `crates/sela-app/src/ui/workspace/filter_bar.rs`.

**Steps to reproduce:**

1. On a table Data tab, operator LIKE, value `100!%`. Apply. Rows include `100%` and other names.
2. Repeat with `a!_b` (row `a_b` exists) and `wow!!` (row `wow!` exists).
3. Or call `sela_core::escape_like_meta` with those strings.

**Expected:** Per `docs/user/filtering.md` and the operator tooltip (“use ! to escape”): `100!%` matches only `100%`, `a!_b` matches only `a_b`, `wow!!` matches only `wow!`. `%` alone stays a wildcard. SQL is `LIKE … ESCAPE '!'` with a bound parameter.

```text
escape_like_meta(wow!!)=wow!!!!
escape_like_meta(a!_b)=a!!_b
```

Under `ESCAPE '!'`, `100!!%` is a literal `!` plus a wildcard, not the row `100%`. The unit test `validate_empty_text_eq_and_reject_null_literal_on_int` locks `a%!b` → `a%!!b`. Legacy contains/starts/ends still escape `%`, `_`, and `!` correctly and are covered by the engine tests; those operators are not in the menu.

**Evidence:** `crates/sela-core/src/filter.rs` `escape_like_meta` and the LIKE arm of `append_condition`; tooltip string in `filter_bar.rs`; probe output above.

**Severity:** major. Not a blocker: `=` and wildcard `LIKE` still work. The documented way to match a literal percent or underscore does not.
