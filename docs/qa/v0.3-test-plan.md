# v0.3 test plan

Test specs for Sela v0.3.0: roadmap M3 (SSH tunnel, autocomplete, export/import, command palette) plus issue [#68](https://github.com/nesso99/sela/issues/68) (optimistic WHERE and cancel for `apply_changes`).

This plan does not change product code. Engineering writes the automated tests named here; QA reviews those PRs against this plan and runs the X11 manual RC round.

## Status of sources

Aligned with the v0.3.0 UX spec PR [#114](https://github.com/nesso99/sela/pull/114) (docs-only, not merged at the time this follow-up was opened — this plan depends on #114 merging) and with the PM decisions treated as fixed: SSH hidden for SQLite; first-seen host key shows a fingerprint and the user can accept, saving to `known_hosts`; changed host key is a hard error with no override in v0.3; no ProxyJump; #68 optimistic WHERE is always on, no setting.

## Scope

**In scope**

- M3-1 SSH tunnel: Use SSH tunnel toggle; password, private key, key + passphrase, ssh-agent; explicit Import from `~/.ssh/config`; known_hosts first-seen Accept & save and changed-key hard error; SSH errors distinct from DB errors. No ProxyJump. Import URL never fills SSH. Hidden for SQLite.
- M3-2 schema + alias autocomplete: auto after `.` or **two** identifier characters; manual `ctrl-space` in the editor; Tab and Enter accept. Optional tree-sitter muted keyword/comment highlight only if it ships.
- M3-3 export of a result or a whole table as CSV, JSON, and SQL INSERT, with background progress and cancel (cancel deletes the partial file); CSV import into an **existing** table only; encodings (UTF-8, optional BOM), NULLs, quoting, large files, and export→import round-trip; safe-mode copy as in the UX spec.
- M3-4 one palette surface: `secondary-p` table mode, `secondary-shift-p` action mode, `>` switches to actions; fuzzy match; keyboard-only use; dimmed disabled commands with a reason. Preview SQL moves to `secondary-shift-v`.
- #68: optimistic `WHERE` always on; cancel of `apply_changes` with no partial commit and the specified status copy.
- Automated regression: existing v0.1 / v0.2 unit, driver, and headless `ui_tests` stay green. This plan does not re-run the v0.2 manual functional checklist.

**Out of scope (do not fail v0.3.0 for their absence)**

- M4 signed packages, real-GPU NFR sign-off, branding leftovers.
- Issue [#58](https://github.com/nesso99/sela/issues/58) GNOME Wayland title bar (still deferred; not tested on Wayland).
- Issue [#72](https://github.com/nesso99/sela/issues/72) M2 grid-editing polish, except the #68 items called out above.
- Unique NOT NULL as a row key (roadmap backlog).
- `sqlformat` / `secondary-shift-f` (still reserved).
- MySQL live TLS (existing follow-up).
- ProxyJump / multi-hop SSH / `ProxyCommand`.
- CSV import that creates a new table (backlog in the UX spec).
- Windows and macOS interactive GUI (CI still builds and runs `cargo test` on those OS; QA’s RC is X11 only, same as v0.2.0).

## Workflow

Per root [AGENTS.md](../../AGENTS.md) and Đức’s v0.3+ rule (automated tests first; manual RC covers only rendering, window manager, and OS behavior on X11):

1. UX publishes the v0.3 spec with acceptance criteria (#114). QA reviews that PR for testability.
2. This plan maps each criterion to a test. SE writes the automated tests in the feature PRs (`#[gpui_kit::test]` under `crates/sela-app/src/ui/ui_tests/`, unit tests, or driver integration tests).
3. QA reviews those PRs against this plan and flags missing tests. A UI change with no `ui_tests` coverage must say why in the PR body, as [AGENTS.md](../../AGENTS.md) already requires. Rebind Preview (`secondary-shift-v`) and the action palette (`secondary-shift-p`) in the same implementation PR — today `secondary-shift-p` is still `PreviewChanges` in `crates/sela-app/src/ui/mod.rs`.
4. DevOps cuts an RC from fully green `main` (`ci-gate`).
5. QA runs the manual X11 round in this plan, files bugs with `bug`, `severity:*`, and `v0.3.0`, and re-verifies fixes.
6. Sign-off: “QA sign-off: no open bugs” plus the RC SHA, to PM and DevOps.

Prefer automation wherever a behavior can be asserted without a real display or a native OS dialog (“cái gì test tự động được thì ưu tiên”).

## Coverage conventions

Each row is one acceptance criterion.

- **ID** — stable test id from the #110 plan where the criterion still exists. New rows added for behaviors #114 specified that had no id (SSH-19…, EX-13, IM-09, PAL-11, PAL-12, OW-05). SE may split a row into several `#[test]` / `#[gpui_kit::test]` functions; keep the id in the test name or a comment so QA can grep the PR.
- **Level** — the primary automated layer. Extra layers in *Asserts* are welcome.
  - `unit` — `sela-core`, `sela-config`, `sela-ssh`, or app logic with no server.
  - `driver` — integration against the named backend (openssh container, Postgres, MySQL, and/or SQLite).
  - `headless UI` — `#[gpui_kit::test]` in `crates/sela-app/src/ui/ui_tests/`.
  - `manual-at-RC` — rendering, window manager, or OS only.
- **Owner** — Engineering writes every automated test. QA writes this plan, reviews PRs, and runs the manual RC column.

### OpenSSH test container

Propose a Linux-only CI job `ssh-integration`, modelled on `db-tls-postgres` (throwaway material, never committed) and the skip-unless-env pattern of `db-integration`.

**Topology**

- A user-defined Docker network.
- `postgres:16` (and `mysql:8.4` if the job stays cheap) **without** publishing `5432`/`3306` to the runner. The database is reachable only from the bastion.
- An `openssh-server` bastion on the same network, publishing `2222:22` to the runner. Password auth and public-key auth both enabled for a throwaway `sela` user.
- Tests on the runner must not be able to open `postgres:5432` directly; they only reach the DB after the tunnel binds `127.0.0.1:<ephemeral>`.

**Script** (SE owns, analogous to `scripts/run-pg-tls.sh`): e.g. `scripts/run-ssh-bastion.sh`. It generates keys, a passphrase-protected key, `known_hosts`, starts the containers, and prints export lines:

```text
SELA_SSH_HOST=127.0.0.1
SELA_SSH_PORT=2222
SELA_SSH_USER=sela
SELA_SSH_PASSWORD=…
SELA_SSH_KEY=…/id_ed25519
SELA_SSH_KEY_PASSPHRASE=…
SELA_SSH_KEY_ENCRYPTED=…/id_ed25519_enc
SELA_SSH_KNOWN_HOSTS=…/known_hosts
SELA_SSH_KNOWN_HOSTS_BAD=…/known_hosts.bad
SELA_SSH_DB_HOST=postgres    # hostname as seen from the bastion
SELA_SSH_DB_PORT=5432
SELA_SSH_MYSQL_HOST=mysql
SELA_SSH_MYSQL_PORT=3306
```

Locally: `eval "$(./scripts/run-ssh-bastion.sh)"` then `cargo test -p sela-ssh` / the driver SSH suite. Tests **skip and pass** when the env is unset; they **fail** when it is set but the bastion is down.

**Job placement:** `ci.yml` on Ubuntu, behind the same `changes` path filter, required by `ci-gate` when code changes. Not required on macOS/Windows CI (no Docker service grid there today). `cargo deny` must stay green when `russh` is added; the allow-list in `deny.toml` is MIT/Apache-first and GPL-incompatible licenses stay banned.

**Agent tests:** start `ssh-agent` in the job, `ssh-add` the unencrypted key, and point the crate at `SSH_AUTH_SOCK`.

## M3-2 — Autocomplete (US-08)

Popup rules in [03-sql-editor.md](../design/ux/03-sql-editor.md) as updated in #114. **AU-01, AU-05, and AU-13 are retargeted** from the #110 plan (2-character auto-trigger; editor-scoped `ctrl-space`; Tab accepts). Ranking and identifier rules should be unit-tested in a pure function (catalog + buffer + caret → suggestions) so the UI tests stay thin.

| ID | Acceptance criterion | Level | Asserts | Owner |
| --- | --- | --- | --- | --- |
| AU-01 | Popup opens after **two** identifier characters, not after the first | headless UI | Typing one identifier character does not open the popup; the second does. An identifier character is a Unicode letter (`Alphabetic`), a Unicode decimal digit (`Nd`), or `_`; on MySQL connections `$` also counts. Other punctuation (including `.`, which has its own rule) does not. The two characters are consecutive in the current unquoted identifier fragment at the caret. | SE |
| AU-02 | Popup opens immediately after `.` | headless UI | `alias.` / `table.` / `schema.` opens without a further character. | SE |
| AU-03 | Popup does not open inside a comment or a string | unit + headless UI | `--`, `/* */`, and quoted literals do not trigger or move the selection. | SE |
| AU-04 | IME composition: popup stays closed; Enter commits the composition and does not accept a completion | headless UI if `TestAppContext` can inject composition; otherwise manual-at-RC (OS/IME) | Document which path landed in the implementation PR. | SE / QA |
| AU-05 | `ctrl-space` (Control+Space, not `secondary`) manually opens or refreshes suggestions in the editor; `secondary-space` stays free | headless UI | Editor-focused `ctrl-space` opens the popup even with no / one character typed. `secondary-space` does not. Assert in `TestAppContext` (a real macOS input-source switch may swallow Control+Space; that is not a product bug — finding 7). | SE |
| AU-06 | Suggestions are dialect keywords plus schema, table, column, and current-statement alias names from the connection catalog cache (the same catalog the sidebar uses) | unit + headless UI | A table visible in the sidebar appears as a completion; keywords match the connection dialect. | SE |
| AU-07 | After `alias.` or `table.`, that relation’s columns are listed first | unit | Column order does not start with unrelated tables’ columns. | SE |
| AU-08 | Ranking: (1) case-insensitive prefix on the typed fragment, (2) columns of tables named in the current statement, (3) other substring matches, (4) keywords below identifiers unless the fragment itself is a keyword prefix | unit | Golden cases for each rule, including a keyword prefix (`SEL` → `SELECT` not buried). | SE |
| AU-09 | Quoted and schema-qualified identifiers | unit + headless UI | Mixed-case, reserved words, and `schema.table` / `"Odd Name"` complete and insert with the correct dialect quoting. Inserted text is valid to run. | SE |
| AU-10 | Large schemas stay usable | unit + headless UI | A catalog of hundreds of tables/columns still returns quickly; the popup shows at most 8 rows and then scrolls; the UI thread is not blocked. | SE |
| AU-11 | Row chrome: monospace name, muted label on the right (`type` / `table` / `schema` / `keyword`); max 8 rows at 22px (≤ 176px) then scroll; width fits labels up to 360px | headless UI | Assert layout bounds the way `file_menu` tests assert trigger size. Paint contrast is manual-at-RC. | SE |
| AU-12 | Placement prefers above the caret; flips below only when there is no room above | headless UI | Editor at the bottom of the window does not clip the popup off-screen. | SE |
| AU-13 | Keys: Up/Down move; **Enter and Tab accept and insert**; Escape closes and leaves the text; click outside closes | headless UI | Buffer after Escape equals buffer before accept. Tab and Enter accept and insert while the popup is open (Tab does not move focus out of the editor). When the popup is closed, Tab inserts a tab / indent in the editor and does not leave the editor. | SE |
| AU-14 | Arrow keys do nothing to the popup when it is closed | headless UI | Left/Right/Up/Down move the caret (or leave the editor) and do not open the popup. | SE |
| AU-15 | Optional MIT tree-sitter SQL grammar: comments in `muted_foreground`, strings in `foreground`, keywords slightly brighter than identifiers | headless UI or unit | **Only if the feature ships in v0.3.0.** No multi-color syntax theme. Skip the test (do not fail the milestone) if the grammar is deferred. | SE |
| AU-16 | Completions follow catalog refresh; loading / empty copy | unit + headless UI | Load on connect. Refresh on Refresh schema (sidebar / palette), after a successful DDL statement run from the editor, and when switching database/schema. While loading, a single muted, not-selectable row `Loading schema…` (Enter must not insert that text). After a successful empty load: `No schema loaded.` (also not inserted). Successful DDL is a finished statement (no error) whose first keyword, after leading comments, is one of `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `COMMENT`, `RENAME`, `ATTACH`, `DETACH` (case-insensitive). Not `GRANT` / `REVOKE`. “Switching database/schema” means: reconnect with a different database name; a successful MySQL `USE …`; a successful Postgres `SET search_path …`; or selecting a different schema in the sidebar when that changes the completion scope for unqualified names. | SE |

## #68 — Optimistic WHERE and cancel for `apply_changes`

Aligned with [08-preview-commit.md](../design/ux/08-preview-commit.md) and the PM decision: optimistic WHERE is **always on**, no setting.

Today, `ChangePlan` `WHERE` clauses use only PK columns, and `DatabaseSession::apply_changes` has no `CancellationToken` (`crates/sela-core/src/session.rs`). UPDATE/DELETE already fail closed with `DbError::ChangeConflict` and rollback when the statement does not affect exactly one row — optimistic WHERE reuses that guard.

| ID | Acceptance criterion | Level | Asserts | Owner |
| --- | --- | --- | --- | --- |
| OW-01 | `UPDATE` / `DELETE` `WHERE` ANDs previous non-PK column values; NULL old values use `IS NULL` | unit | Golden / snapshot tests in all three dialects, extending `crates/sela-core/tests/change_plan_snapshots/`. PK predicates remain. Values stay bound, never interpolated. Preview SQL (`preview_sql` / `preview_bound`) includes the extra predicates. | SE |
| OW-02 | A concurrent non-PK edit is detected as zero rows affected | driver (PG, MySQL, SQLite) | Out-of-band `UPDATE` of a non-PK column on the same PK, then Commit: `ChangeConflict`, transaction rolled back, pending changes kept. Existing PK-conflict cases still pass. | SE |
| OW-03 | Commit still succeeds when no concurrent change happened | driver (3 engines) | A normal grid edit commits; the extra WHERE does not false-positive (including a same-value UPDATE; MySQL still uses `FOUND_ROWS`). Nullable non-PK columns whose old value is NULL succeed. | SE |
| OW-04 | Preview lists the optimistic predicates | unit + headless UI | The Preview sheet text matches the plan. Preview opens with the **Preview** button or `secondary-shift-v` (not `secondary-shift-p`) when the table Data pane, pending bar, or sheet is focused. The button label is unchanged. | SE |
| OW-05 | Conflict UI offers Refresh | headless UI | Banner + status: `Row changed since it was loaded. No changes were saved. Refresh and try again.` A **Refresh** button on the banner drops that tab’s `ChangeSet` and reloads the page. Discard remains available. The older `No row matched {schema.table} for this key.` line may appear as detail in the banner body when the driver names the table; the primary copy is the new sentence. | SE |
| CAN-01 | `apply_changes` accepts a `CancellationToken`; Stop, `secondary-.`, and pending-bar **Cancel** cancel a commit in flight | unit (API) + headless UI | While running: pending bar / status `Committing {N} changes…`; Commit button disabled, label `Committing…`; Cancel enabled (ghost). The UI Commit path wires the same cancel token as streaming queries. Mutations, paging, filter, and sort stay blocked (existing rule). | SE |
| CAN-02 | Cancel mid-apply leaves no partial commit | driver (PG, MySQL; SQLite if feasible) | Hold a row lock (or otherwise block a multi-statement plan) so the transaction is in flight, then cancel. After rollback, none of the plan’s writes are visible. Pending changes are kept. | SE |
| CAN-03 | Cancelled commit is not reported as success | headless UI + driver | Banner / status: `Commit cancelled. No changes were saved.` (not `Committed · N statements`). Edits remain dirty. A later Commit can succeed. | SE |
| CAN-04 | A commit that is not cancelled is unchanged aside from optimistic WHERE | driver (3 engines) | Existing `apply_changes` success tests stay green with the new token (pass an uncancelled token). Success UI is still `Committed · N statements · … ms` (reload failure still `Committed · the page failed to reload.`). | SE |

SQLite has no server-side query cancel today (documented M1 limitation). For CAN-02 on SQLite, cancel between statements or at a cooperative check still must roll back; if a blocked SQLite writer cannot be interrupted, document that limitation in the implementation PR and still cover PG and MySQL.

## RC exit criteria

v0.3.0 is ready for QA sign-off when all of the following hold on the RC commit:

1. **CI green** — `ci-gate` is success on the RC SHA, including `ssh-integration` once that job exists. Docs-only follow-ups may skip heavy jobs via the existing path filter; the RC itself is cut from a fully green `main`.
2. **Automated coverage in this plan is implemented and passing** — every acceptance-criterion row in this plan has an automated test, or a documented reason in the implementation PR why it cannot be automated. AU-15 may be skipped if tree-sitter did not ship. AU-04 may be manual-at-RC if composition cannot be injected.
3. **Manual X11 round passed** — every `M-*` row above is pass or an explicit, filed waiver (not a functional gap).
4. **No open issues** labelled both `bug` and `v0.3.0`. Every such bug was re-verified after the fix landed.
5. **QA + PM sign-off** — QA sends “QA sign-off: no open bugs” with the SHA to PM and DevOps. DevOps tags only after both have signed off.

Windows and macOS interactive GUIs, and Wayland, are not gates. Caveat them in the sign-off the same way as v0.2.0.
